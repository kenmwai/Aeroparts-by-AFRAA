# AeroParts.Market

B2B marketplace for certified aircraft parts. Sellers list inventory with photos and airworthiness certificates (8130-3, EASA Form 1, trace docs). Buyers browse, review documentation, and send structured RFQs. Confirmed deals auto-generate a compliant commission invoice.

## Tech stack

- **Frontend**: React 19, TanStack Start (SSR + file-based routing), TanStack Query, Tailwind CSS 4, shadcn/ui
- **Backend**: Supabase (Postgres, Auth, Storage, RLS)
- **Server logic**: TanStack `createServerFn` + Postgres `SECURITY DEFINER` functions for deal confirmation
- **PDF**: `jsPDF` for aviation-compliant invoices
- **Hosting**: Cloudflare Workers (edge SSR)

## Architecture

```
 Browser ──► TanStack Start (edge SSR) ──► Supabase (Postgres + Auth + Storage)
                    │
                    └─► createServerFn (RPCs, service-role only where needed)
```

Every user-owned table has RLS enabled and policies scoped to `auth.uid()`. Privileged operations (deal confirmation, invoice creation) run through `SECURITY DEFINER` Postgres functions so pricing and commission cannot be tampered with client-side.

### Key domain tables

| Table | Purpose |
|---|---|
| `profiles` | Company + billing details, one per auth user |
| `parts` | Inventory listings with condition (NE/NS/SV/AR/OH/RP), export data (ECCN, country of origin) |
| `part_images`, `certificates` | Private storage refs (signed URLs, 1 h TTL) |
| `quote_requests` | RFQ lifecycle: pending → responded → confirmed |
| `invoices` | Immutable snapshot generated by `confirm_deal()` — part, seller, buyer, commission rate at time of sale |
| `platform_settings` | Global commission rate (admin-editable) |
| `user_roles` | RBAC (`admin` role) — separate table to prevent privilege escalation |

## Scaling to 1M+ users

### Database indexes (shipped)
- `parts (status, created_at DESC)` — catalog listing
- `parts (seller_id, created_at DESC)` — seller dashboards
- `parts (part_number)`, `parts (manufacturer)`, `parts (ata_chapter)`, `parts (condition)` — filters
- **GIN full-text index** on `parts.search_tsv` (generated column: part_number^A, title^B, manufacturer^C, aircraft_model^C)
- **pg_trgm GIN index** on `parts.part_number` for substring/prefix matches
- `quote_requests (buyer_id, created_at DESC)`, `(seller_id, created_at DESC)`, `(part_id)`, `(status)`
- `invoices (seller_id, issued_at DESC)`, `(buyer_id, issued_at DESC)`, `(rfq_id)`
- `part_images (part_id)`, `certificates (part_id)`, `user_roles (user_id)`

### Query patterns
- **Catalog** uses server-side FTS + trigram search with `range()` pagination (24/page), debounced 250 ms. No client-side filtering of large sets.
- **Signed URLs** batched via `createSignedUrls` (single round trip per page) instead of N sequential calls.
- Images use `loading="lazy"` + `decoding="async"`.

### Recommended next steps (not shipped)
1. **Move seller dashboard data to TanStack Query** with per-tab `queryKey`s and `staleTime: 60_000`. Currently uses `useState` + parallel fetches — works but no cache, refetches on every mount.
2. **Paginate dashboard invoices/RFQs** (`.range()` + cursor) — unbounded today.
3. **Materialized view** for popular filters (by manufacturer, by ATA chapter) if catalog QPS gets heavy; refresh via `pg_cron` every 5 min.
4. **CDN in front of signed image URLs**: switch bucket to public + signed transformer, or add Cloudflare Image Resizing.
5. **Read replica** for catalog reads once write load justifies it.
6. **Rate limiting** on RFQ submission (per buyer, per part) — Postgres unique-per-window or a Cloudflare Worker in front.
7. **Realtime** on RFQ inbox via Supabase realtime channels scoped to `seller_id`.

### Security posture
- RLS on every `public` table; explicit `GRANT`s per role.
- Roles in a separate `user_roles` table; checked via `SECURITY DEFINER` `has_role()` — no client-writable role columns.
- `confirm_deal()` verifies the caller is the buyer and locks price/commission server-side.
- Storage buckets `part-images` and `certificates` are **private**; all access via short-lived signed URLs.
- Server functions read secrets only inside handlers (`process.env`), never at module scope.

## Invoicing & compliance

`confirm_deal(rfq_id)` (Postgres SECURITY DEFINER) atomically:
1. Validates caller = buyer and RFQ status = `responded`
2. Snapshots part (title, P/N, S/N, ECCN, country of origin, certificates), seller (company, tax ID, address), buyer (email, phone)
3. Applies the current `platform_settings.commission_rate` (1% default)
4. Writes an `invoices` row with a sequential `INV-YYYY-NNNNNN` number

PDF includes ATA Spec 2000 traceability data, EAR/ITAR export-control statements, and totals part price + commission fee.
